# SkyDispatch Docs

Start here, then follow the links below. These are living documents — update them in
the same PR as the decision they describe changes, not after the fact.

- [nfr.md](./nfr.md) — Non-functional requirements: performance, offline behavior,
  reliability/safety, security & privacy, accessibility, device support, localization,
  data retention.
- [tech-stack.md](./tech-stack.md) — Confirmed technology decisions and why, plus
  known cross-cutting risks.
- [architecture.md](./architecture.md) — How the manual's three surfaces
  (Dispatcher-App / Registration / Terminal board) map to the real system, data flow
  between them, domain-model naming, and open (unresolved) decisions.
- [definition-of-done.md](./definition-of-done.md) — Checklist for calling a change
  done.
- [SkyDispatch-Benutzerhandbuch.docx](./SkyDispatch-Benutzerhandbuch.docx) — the
  original German user manual these requirements are derived from. Source of truth
  for user flows; the docs above are the engineering interpretation of it.
